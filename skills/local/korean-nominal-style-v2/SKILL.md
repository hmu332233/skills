# korean-nominal-style-v2

사용자가 지정한 한국어 원문에만 적용하는 재작성 스킬이다. 세션 응답 문체는 별도 요청에 따른다.

핵심은 **의미 압축**이다. 명사구로 핵심을 전달하되, 어휘 사이의 관계가 분명하게 남는 범위에서 조사와 어미를 줄인다. 의미와 사용자 지정 형식을 간결성보다 우선한다.

## 작업 순서

1. **범위 확정.** 지정된 원문 전체를 읽고, 아래 보존 규칙에 따라 수정할 구절과 유지할 부분을 구분한다. 대상 파일·구절과 보호할 문자열이 식별되면 다음 단계로 진행한다.
2. **의미 압축.** 아래 표현 규칙으로 각 대상 구절을 다듬는다. 뜻을 확신할 수 없는 구절은 원문을 유지하고 모호한 지점을 표시한다. 모든 대상 구절이 재작성되거나 보류 사유가 확인되면 다음 단계로 진행한다.
3. **대조 검토.** 수정한 구절마다 원문과 결과를 대조한다. 아래 의미·문자열·구조 보존 항목이 모두 유지되고, 원문이나 제공된 맥락에 없는 정보가 추가되지 않았을 때 완료한다. 차이가 있으면 해당 구절을 다시 다듬거나 원문을 유지한다.
4. **전달.** 붙여 넣은 글은 변환 결과만 반환한다. 파일은 변경을 저장한 뒤 실제 차이가 지정 범위에만 있는지 확인하고 수정 파일과 범위를 보고한다. 보류한 구절이 있으면 이유를 짧게 덧붙인다. 전후 비교나 해설은 요청받은 경우 제공한다.

## 표현 규칙

- 제목·상태·단순한 작업 항목은 명사구 종결 우선: `요청 실패 시 최대 3회 재시도 필수`
- 주체·대상·방향·조건을 구분하는 조사와 수식절 유지: `관리자가 사용자 권한 변경`, `비용을 추론하는 함수에 오류 발생 시 집계 중단`
- 명사구만으로 동작이나 상태가 불분명하면 `~함`·`~됨` 또는 필요한 서술어 사용: `작업 완료 전까지 연결을 유지해야 함`
- 조건·원인·예외가 복잡하거나 질문·경고의 뜻이 흐려지면 완전한 문장 사용. 인과·대조·시간 관계는 접속사나 수식절로 명시
- 맥락에 맞는 익숙하고 정확한 어휘와 구체적인 행동 표현 사용: `설정을 코드에 명시`. 의미가 분명한 한자어와 분야에서 정착된 관용 표현은 유지
- 개조식 항목의 끝 마침표는 주변 형식에서 요구할 때만 사용. 완전한 문장에는 정상적인 문장 부호 사용

## 보존 규칙

**의미:** 아래 요소를 원문과 같은 뜻과 강도로 유지한다.

- 조건, 예외, 제외 대상, 부정
- 의무, 권고, 허용, 가능성, 불확실성
- 수량, 범위, 상한·하한과 경계값: 이상/초과, 이하/미만 구별
- 주체, 대상, 원인, 목적, 의존 관계, 순서, 시점
- 계획·진행·완료 상태

사실 오류가 의심되는 구절도 원문을 유지하고 의심되는 지점만 알린다. 내용 정정은 별도 요청에 따른다.

**문자열:** 코드, 식별자, 경로, 명령어, URL, 인용문, 로그, 오류 메시지, UI 문구, 제품명, 프로젝트 용어와 기존 외국어 표현의 표기·대소문자를 그대로 유지한다.

**구조:** Markdown 제목·목록, 코드 블록, 들여쓰기, 문단·줄 구조와 주석 기호 안에서 다듬는다. 코드 주석은 사용자가 재작성 대상으로 지정한 경우에만 한국어 설명 부분을 수정한다.
